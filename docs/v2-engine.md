# v2 逐幀引擎（footballsim.sim）

v1（`footballsim.engine`）是事件驅動的引擎，已以真實資料校準，作為對照基準保留（提交 `c226684`）。v2 是 10 Hz 逐幀引擎，
目標是讓攻防轉換、跑位與逼搶「被算出來」，並精確累計跑動距離。只要統計，不輸出動畫或 tracking。

執行：`python -m footballsim tickmatch --home 0 --away 1 --seed 0`（單場，約 10 秒）。參數：`config/sim_params.yaml`。

## 一、架構

屬性、複合能力、當日狀態、亂數流、威脅網格、決策與陣型函式、事件格式與統計都沿用 v1；v2 的 `World` 內含一個 v1 `MatchSim`
當作屬性與參數的提供者（不呼叫它的主迴圈）。

| 模組 | 內容 |
|---|---|
| `world` | 狀態：22 人（位置、速度、體能、意圖、被過掉的暫停秒數、跑動距離）、球（位置、速度、模式 CARRIED / FLIGHT / FREE / DEAD）、兩隊階段、時鐘、事件 |
| `physics` | 球：飛行用解析式（地面球等減速、高球加拋物線高度）、線段對點的掃掠偵測（一個 tick 球移動 2–3 m，不掃掠會穿過球員）；球員：加速度與減速度有上限的轉向，最高速取自屬性，加速能力取自 v1 的 tau，體能與跑動距離逐幀累計 |
| `phase` | 階段機 IP / DT / OOP / AT；球權改變時失球方進 DT、得球方進 AT；DT 窗口內離球最近的 N 人反搶；事件 TURNOVER、PRESS_RECOVERY、COUNTER_ATTACK |
| `shape` | 目標點：呼叫 v1 陣型函式（縱向層次、資料基準的橫向分布、盯人、逼搶位置），關掉 v1 的位置連續性與逼搶趕到距離上限，改由運動學決定；目標點指數平滑；意圖（HOLD / RUN / PRESS / RECOVER / RECEIVE / CHASE / CARRY）決定速度比例 |
| `play` | 決策（v1 `choose` 當評分函式）、持球者狀態機（決策 → 等待持球時間 → 出腳動作 → 起腳）、傳球落點誤差、飛行中的攔截（掃掠）、接球控制、無主球、搶斷、過人決勝、射門 |
| `rules` | 出界（界外球、球門球、角球）、進球、重啟（發球者走到發球點）、半場；越位、犯規、牌、換人、傷病在第四階段 |
| `engine` | 主迴圈與結果（`MatchResult`，與 v1 相容，統計模組不用改） |

## 二、一個 tick（0.1 秒）

```
1 球運動並做掃掠偵測          ← 上一 tick 的球狀態
2 接觸判定：攔截、到達控制、無主球、搶斷   ← 1 與球員位置
3 持球者動作：決策、等待、出腳、起腳       ← 2
4 規則：出界、進球                          ← 1、3
5 階段更新：球權改變觸發、窗口倒數          ← 2
6 目標點（每 1 s，球權改變與重啟時立即）    ← 5
7 無球意圖（每 0.5 s）                      ← 6
8 移動積分：轉向、體能、跑動距離            ← 6、7，持球推進與接球的意圖每 tick 套用
9 時鐘與統計（控球、球在場時間）
```

## 三、設計取捨（已與使用者確認）

1. **結果由物理算**：傳球、攔截、搶斷由到達時間差與距離決定；射門沿用 v1 的三階段結果（封堵、射正、門將），球的彈道依結果動畫。
   v1 擬合的傳球成功率只用在決策時的預期與驗證目標，v2 湧現的完成率要接近它。
2. **決策重用 v1**：`play.decide` 把 v2 的狀態轉成 v1 `choose` 要的輸入（持球隊座標、越位線、持球時間），選項變成「意圖」：
   起腳後球飛行，結果由接觸決定。
3. **持球時間**：沿用 v1 的持球時間分布，進攻轉換窗口內縮短（`at_hold_factor`）。
4. **重啟簡化**：出界後由最近的球員（球門球由門將）走到發球點，用 v1 的重啟模式決策（短傳為主）；進球後 30 秒開球。

## 四、模型假設（沒有資料可直接擬合；待用追蹤資料校準）

`config/sim_params.yaml` 的所有係數都是假設或粗略值，尚未校準，主要有：

| 參數 | 值 | 說明 |
|---|---|---|
| `motion.vmax_scale` | 0.88 | 最高速 = v1 的 vmax × 此值（追蹤資料第 99.9 百分位 7.9 m/s，v1 的平均球員 9.0 m/s 偏快） |
| `motion.a_max` / `a_dec` | 5.5 / 6.5 m/s² | 加速度、減速度上限（追蹤資料 \|a\| 第 99.9 百分位約 5.3）；再乘 v1 tau 決定的加速能力 |
| `motion.frac.*`、`arrive_tau` | 見檔案 | 各意圖的速度比例；保持陣型時小幅調整很從容（速度 = 距離 / arrive_tau） |
| `shape.smooth` | 0.3 | 目標點的平滑係數（v1 每次重算都重抽位置誤差） |
| `contest.intercept_*`、`control_*`、`tackle_*` | 見檔案 | 攔截、接球控制、搶斷的 logit 係數 |
| `phase.dt_window` / `at_window` / `counter_press_n` | 4 s / 5 s / [1,2,2,3,4] | 轉換窗口與反搶人數（可用 SkillCorner 的 phases_of_play 與 StatsBomb 的 counterpress、From Counter 校準） |
| `ball.*` | 見檔案 | 傳球初速、減速度、高球速度與高度、落點誤差、控制半徑 |

## 五、測試

`tests/test_sim_core.py`（13 項）與 `tests/test_sim_match.py`（5 項）；全部測試 74 項通過。

- 動力學：速度與加速度不超過上限；加速與衝刺屬性高者 30 m 較快；跑動耗能。
- 球：地面球到達時間與閉式解差 < 2%；高球落在目標、最高點在中間；掃掠偵測不穿過球員；進球只在球門柱之間且低於橫桿。
- 接觸：防守者不在球路上就不會攔截、能力高者攔截較多；搶斷成功率隨雙方能力。
- 階段：只在球權改變時切換、窗口到期回到 OOP / IP、反搶成功緊接在失球之後；press 高則反搶人數多、體能低則窗口短。
- 陣型：目標點在場內；防線高度戰術改變後方人的位置。
- 決策回歸：相同狀態與亂數流下，v2 的決策與 v1 `choose` 完全一致。
- 性質：同種子完全重現、不同種子不同；每個 tick 球員在場內、沒有瞬移、球的模式一致；事件重建出統計；效能紀錄（10 模擬分鐘約 1.2 秒）。

## 七、MVP 範圍外（後續階段）

- 第三階段：新陣型（3-4-3、4-1-4-1、3-2-5）與角色（內收邊衛、防守型與組織型後腰、內切邊鋒、偽九號）；動態陣型變化；邊路進攻、中路滲透。
- 第四階段：越位、犯規、牌、完整定位球（角球傳中、任意球、點球）、換人、傷停補時、傷病。
- 第五階段：用追蹤資料校準移動與球物理，用事件資料校準攔截、搶斷與反搶，對照 v1 的 42 項指標與位置分布。
