# 屬性驅動足球模擬系統 — 設計方案（Python）

> 版本 v0.1 · 2026-11-24 · 狀態：M0、M1 已實作，M4 第七輪：以 StatsBomb 360 校準前場站位、邊路與紅牌（進行中）（實作現況見 [calibration-status.md](calibration-status.md)）
>
> 本文標示 **✔ 已驗證** 的數字，皆由附錄 A 的程式碼實際執行得出；標示 **實測** 的統計，來自 football-data.co.uk 2022/23–2025/26 五大聯賽共 7,082 場比賽（計算腳本見附錄 C）。

---

## 0. 摘要

採用 **「事件驅動 + 戰術快照 2D 座標」** 的比賽引擎，讓 **60 項球員屬性** 透過 **「位置 → 決策 → 執行 → 狀態」四層機制** 影響每一個動作的機率。每個動作的基準機率由真實事件資料擬合；整場與整季的結果，再用真實聯賽統計做蒙地卡羅校準。最後用敏感度分析證明每個屬性都**真的有用，而且沒有任何一個無敵**。

| 決策點 | 方案 | 理由 |
|---|---|---|
| 引擎型態 | 事件驅動；每個事件前更新 22 人的戰術座標，不做逐幀物理 | 保有越位、身後空間、壓迫、包夾等空間上的真實感，同時讓 Python 跑得動上萬場校準 |
| 屬性量表 | 1–100 絕對量表；R = 65 為頂級聯賽平均 | 跨聯賽可比；所有公式都有明確基準點 |
| 機率模型 | 在 logit 空間：真實基準率 ＋ 屬性差偏移 | 平均球員的表現由資料決定，屬性只決定「好多少、差多少」 |
| 物理量 | 身高 cm、速度 m/s、距離 m、時間 s | 速度、身高的價值會隨情境自然變化，不會無腦強 |
| 校準基準 | football-data（整場／賽季層）＋ StatsBomb 開放資料（事件層） | 「符合現實」可以量化驗收 |
| 屬性有效性 | 自動化敏感度分析 ＋ 死屬性／壓倒性屬性測試 | 「屬性真的影響結果」可以被證明，也能做回歸測試 |

## 1. 設計目標與原則

### 1.1 目標

1. 輸入兩隊名單、戰術與比賽情境，輸出一場完整比賽：逐事件紀錄、比分、技術統計、進階數據（xG / xA / xT）、球員評分、體能數據。
2. 大量模擬時，各項統計的**平均值與分布**都落在真實頂級聯賽的範圍內（§6）。
3. 任一屬性的差異，都會在球員個人數據與球隊結果中產生**方向正確、幅度合理、可量測**的差異。

### 1.2 設計原則

| # | 原則 | 具體做法 |
|---|---|---|
| P1 | 屬性決定機率，不決定結果 | 所有結果都是機率抽樣。足球低比分、高變異：實測中，賠率上的熱門只贏下 54.1% 的比賽 |
| P2 | 基準來自資料，屬性只負責偏移 | 「R 水準球員在此情境下的成功率」由事件資料擬合；屬性差在 logit 空間平移 |
| P3 | 情境決定屬性價值 | 速度在有空間時才值錢、身高只在高球時有用、冷靜只在受壓時生效 |
| P4 | 物理量有物理意義 | 衝刺用 Furusawa 加速模型；爭頂用「身高 + 起跳高度」 |
| P5 | 沒有死屬性 | 每個屬性至少進入一個機制，並由敏感度測試自動把關 |
| P6 | 參數外部化、可重現 | 所有係數放 YAML；每場比賽有隨機種子，可完整重播 |
| P7 | 分層解耦 | 資料／引擎／分析／賽季／校準 五層各自可獨立測試 |

## 2. 系統總覽

```
  ┌──────────────┐      ┌────────────────────────────────────────────────┐
  │ 資料層 data   │      │ 比賽引擎 engine                                  │
  │ 球員・球隊    │─────▶│ 賽前準備 → 主迴圈 [快照 → 決策 → 解析 → 套用]    │
  │ 戰術・情境    │      │          → 賽後結算                              │
  │ 規則          │      │ pitch · shape · decision · resolve · fatigue    │
  └──────▲───────┘      │ referee · injury · manager_ai                   │
         │              └────────────────────────┬───────────────────────┘
         │                                       │ 事件流（SPADL 相容）
         │                                       ▼
  ┌──────┴───────┐      ┌────────────────────────────────────────────────┐
  │ 賽季層 season │◀─────│ 分析層 analytics                                 │
  │ 賽程・恢復    │      │ 技術統計 · xG/xA/xT · 評分 · 視覺化 · 文字直播  │
  │ 傷病・成長    │      └────────────────────────────────────────────────┘
  └──────────────┘
       校準層 calibration：目標統計 · 批次模擬 · 自動調參 · 敏感度分析 · 回歸測試
```

**單場流程**

1. **賽前**：載入名單 → 抽樣「當日狀態」（穩定性、大場面、士氣、比賽感覺）→ 預先計算每位球員的複合能力、衝刺參數、有效高度 → 建立兩隊陣型模板。
2. **賽中**：對每個事件依序執行：更新 22 人快照 → 持球者決策 → 屬性對抗解析 → 套用結果（比分、控球、統計）→ 裁判判定 → 傷病檢查 → 扣除體能 → 教練 AI → 推進時鐘。
3. **賽後**：彙整統計與評分 → 回寫賽季層（體能、傷病、停賽、士氣、近況、訓練負荷）。

## 3. 資料模型（數據維度）

### 3.1 量表與單位

- **能力屬性**：1–100 整數，採**絕對量表**（不同聯賽可直接比較）。R = 65 約為頂級聯賽平均，85 以上是世界級，50 左右是次級聯賽平均，30 以下是業餘水準。
- 因為是絕對量表，低級別聯賽會自然出現較多傳球失誤，但進球數不一定較少（雙方都較弱）。這點會用英冠資料交叉驗證（§6.4）。
- 物理量用真實單位；機率用 0–1；特質強度用 0–1。
- 引擎內部把屬性攤平成 numpy 向量（以 IntEnum 為索引）。**複合能力 = 屬性向量 · 權重向量**，權重寫在設定檔，調參時不必改程式（見 §3.12）。

### 3.2 基本資料

| 欄位 | 型別 | 在引擎中的作用 |
|---|---|---|
| player_id、name、short_name | str | 識別、顯示、文字直播 |
| birth_date | date | 年齡 → 成長與老化曲線、恢復速度、傷病風險 |
| nationalities | list[str] | 語言與文化 → 默契成長速度、適應力 |
| height_cm | int | 爭頂有效高度、門將撲救範圍；生成時與敏捷呈負相關 |
| weight_kg | float | 身體對抗（與力量共同作用）；生成時與加速呈負相關 |
| preferred_foot | L / R / B | 判定動作需要用哪隻腳（例：右腳球員在左路 → 內切射門、內旋傳中） |
| weak_foot | 1–100 | 非慣用腳的射門、傳球、傳中品質 |
| 管理層選配：合約、薪資、身價 | — | 不進入比賽引擎 |

### 3.3 能力屬性（60 項）

**身體（8）**

| 鍵名 | 名稱 | 定義 | 在引擎中的作用 |
|---|---|---|---|
| acceleration | 加速 | 從靜止到全速的快慢 | 衝刺模型的時間常數 τ；短距離搶點、啟動、上前壓迫 |
| sprint_speed | 速度 | 最高跑速 | 衝刺模型的 v_max；身後球、反擊、長距離回追 |
| agility | 敏捷 | 變向與轉身 | 過人的攻防兩端、狹小空間持球 |
| balance | 平衡 | 受碰撞時保持控制 | 帶球被碰撞時保有球權、受干擾時的射門品質 |
| strength | 力量 | 身體對抗 | 護球、肩並肩對抗、爭頂碰撞、搶斷；降低接觸傷害 |
| jumping | 彈跳 | 垂直起跳高度 | 爭頂有效高度（起跳 35–65 cm） |
| stamina | 耐力 | 體能消耗速度 | 每分鐘的能量流失率 |
| natural_fitness | 恢復力 | 恢復與抗老化 | 中場與賽間恢復、老化衰退速度、傷後恢復 |

| shielding | 護球 | 背身保護球 | 支點中鋒做球、受壓時保有球權、拖延時間 |
| short_passing | 短傳 | 25 m 以內的地面傳球 | 傳球成功率、球速品質（影響接球者受到的壓力） |
| long_passing | 長傳 | 超過 25 m 及空中傳球 | 轉移、長傳衝吊、長距離直塞 |

|---|---|---|---|

### 3.4 位置熟練度與角色

- **14 個位置**：GK、CB、LB、RB、LWB、RWB、DM、CM、LM、RM、AM、LW、RW、ST。每位球員對每個位置各有 0–100 的熟練度。
- **非本位懲罰**：只作用在「站位類」屬性（def_positioning、off_the_ball、decisions、teamwork），乘上 `0.80 + 0.20 × 熟練度/100`；技術與身體屬性不受影響。例如中衛客串左後衛（熟練度 60），上述屬性 ×0.92。
- **角色**決定持球時的位置模板、移動傾向、動作偏好與能量消耗倍率。角色適配度由屬性加權即時算出，不另外儲存。

| 位置 | 角色範例 | 行為差異 | 關鍵屬性 |
|---|---|---|---|
| GK | 傳統門將／清道夫門將 | 站位深淺、出擊頻率、短傳組織 | 反應、站位／清道夫、短傳、加速 |
| CB | 防守型／出球型／覆蓋型 | 出球選擇、前頂或回收 | 盯人、頭槌、力量／短傳、長傳、冷靜／速度、預判 |
| 邊衛 | 防守型／套邊／內收／翼衛 | 進攻時的位置、傳中頻率 | 搶斷、站位／耐力、傳中、速度／短傳、決策 |
| DM | 屏障／拖後組織／撲搶 | 留守或前插、出球角色 | 站位、預判／短傳、視野／搶斷、侵略性、耐力 |
| CM | 全能中場（B2B）／組織／前插 | 攻守覆蓋範圍 | 耐力、投入度／短傳、視野／無球跑位、終結 |
| AM、邊路 | 10 號／內切邊鋒／傳統邊鋒／邊路前鋒 | 內切或下底、射門或傳中 | 視野、腳法／盤球、終結、逆足方向／傳中、速度 |
| ST | 支點／抓點／回撤（偽九號）／壓迫型 | 背身做球、搶點、回撤串聯、前場壓迫 | 力量、護球、頭槌／無球跑位、終結、預判／短傳、視野／投入度、侵略性 |

### 3.5 特質（習慣動作）

特質**只改變「選擇」，不改變「能力」**。它乘在對應選項的效用上（強度 0–1），因此「愛遠射但遠射能力差」的球員會浪費球權，這正符合現實。

| 類別 | 特質 |
|---|---|
| 進攻 | 內切射門、愛遠射、愛直塞、愛過人、二過一、早傳中、下底傳中、後插上、遊走越位線、回撤接應、背身做球、挑射門將、一腳射門、花式動作 |
| 防守 | 好鏟球、站立防守 |
| 門將 | 好出擊、偏好拳擊、偏好短傳出球 |

### 3.6 動態狀態

**賽中**

| 欄位 | 範圍 | 作用 |
|---|---|---|
| energy | 0–1 | 身體與心智屬性的乘數（§4.13） |

### 3.12 Python 資料結構（節錄；完整版 ✔ 已驗證可執行，pydantic 2.13 / Python 3.10）

pydantic 負責 I/O 驗證；引擎的熱路徑只使用 numpy 向量。以下省略的類別（Shooting、Foot、Position、Development、Condition 等）都依 §3.2–§3.7 的欄位定義。

```python
from typing import Annotated, Dict, List
from enum import Enum, IntEnum
from datetime import date
import numpy as np
from pydantic import BaseModel, Field

Attr = Annotated[int, Field(ge=1, le=100)]
Pct = Annotated[float, Field(ge=0.0, le=1.0)]

class Physical(BaseModel):
    acceleration: Attr; sprint_speed: Attr; agility: Attr; balance: Attr
    strength: Attr; jumping: Attr; stamina: Attr; natural_fitness: Attr

class BallSkills(BaseModel):
    first_touch: Attr; dribbling: Attr; shielding: Attr; short_passing: Attr
    long_passing: Attr; crossing: Attr; technique: Attr

# Shooting、Defending、Mental、SetPieces、Goalkeeping、Hidden 依 §3.3 同樣定義（略）

class Player(BaseModel):
    player_id: str
    name: str
    birth_date: date
    nationalities: List[str]
    height_cm: Annotated[int, Field(ge=150, le=210)]
    weight_kg: Annotated[float, Field(ge=50, le=110)]
    preferred_foot: Foot
    weak_foot: Attr
    physical: Physical
    ball: BallSkills
    shooting: Shooting
    defending: Defending
    mental: Mental
    set_pieces: SetPieces
    goalkeeping: Goalkeeping
    hidden: Hidden
    positions: Dict[Position, Annotated[int, Field(ge=0, le=100)]]  # 位置熟練度
    traits: Dict[str, Pct] = {}                                       # 特質強度
    development: Development
    state: Condition = Condition()                                    # 賽間動態狀態

    def attr_vector(self) -> np.ndarray:
        groups = (self.physical, self.ball, self.shooting, self.defending, self.mental,
                  self.set_pieces, self.goalkeeping, self.hidden)
        return np.array([v for g in groups for v in g.model_dump().values()], dtype=np.float32)

# 屬性索引由模型欄位自動產生，保證與 attr_vector 的順序一致
_GROUPS = (Physical, BallSkills, Shooting, Defending, Mental, SetPieces, Goalkeeping, Hidden)
ATTR = IntEnum("ATTR", [n.upper() for g in _GROUPS for n in g.model_fields], start=0)

def compile_weights(weights: Dict[str, float]) -> np.ndarray:
    """設定檔的 {屬性: 權重} → 權重向量；複合能力 = attr_vec @ w"""
    w = np.zeros(len(ATTR), dtype=np.float32)
    for name, val in weights.items():
        w[ATTR[name.upper()]] = val
    return w / w.sum()
```

驗證輸出：`n_attr = 60 | vector len = 60`，`ATTR.FINISHING` 的索引與 `player.shooting.finishing` 的值一致。

### 3.13 球員生成器（M0）

在沒有真實資料的情況下，屬性分布必須「像真的」：

- **依位置原型生成**：每個位置有一組屬性平均值，再用多元常態分布抽樣，並帶入相關性。例如中衛的頭槌、彈跳、力量彼此正相關；邊鋒的速度、加速、盤球彼此正相關。
- **身高與體重依位置**：門將約 190 cm、中衛約 187、邊衛約 178、中場約 180、邊鋒約 175、中鋒約 183，標準差約 5–6 cm。身高越高，敏捷與加速平均越低。
- **年齡效果**：依 §8 的年齡曲線調整屬性。
- **聯賽水準**：以「能力預算」控制整體水準，頂級聯賽平均約 65、次級聯賽約 55。

## 4. 比賽引擎

### 4.1 引擎型態比較

| 方案 | 做法 | 優點 | 缺點 | 結論 |
|---|---|---|---|---|
| A. 純統計模型 | 隊伍強度 → Poisson 比分 | 快、容易校準 | 個人屬性被平均掉，也沒有比賽過程 | 只當驗證基準 |
| B. 區域事件鏈 | 球場切格，球員以機率分布出現在格子裡 | 快、容易實作 | 越位、身後空間、包夾只能粗略近似 | 可作為最快速的原型 |
| **C. 快照式 2D 事件引擎** | 每個事件前更新 22 人的戰術座標，動作以「幾何 + 屬性」解析 | 空間真實、屬性作用自然、可輸出類 tracking 資料、Python 跑得動 | 實作比 B 複雜 | ✅ **採用** |
| D. 連續物理模擬 | 10–25 Hz 逐幀運算、轉向行為、球的物理 | 最真實，可以直接做動畫 | 慢、難校準、AI 複雜 | 未來的視覺化版本 |

### 4.2 主迴圈（虛擬碼）

```python
class MatchEngine:
    def run(self) -> MatchResult:
        self.pre_match()                                     # 當日狀態、預計算、陣型
        self.restart(Restart.KICK_OFF, team=self.coin_toss())
        while not self.clock.finished():
            s = self.state
            if s.ball.dead:
                ev = self.set_pieces.resolve(s)              # 開球、界外、球門球、角球、自由球、十二碼
            else:
                self.shape.update(s)                         # ① 位置層：22 人戰術快照
                carrier = s.ball.carrier
                options = self.decision.generate(carrier, s) # ① 感知：以視野過濾選項
                choice = self.decision.select(carrier, options, s)  # ② 決策層
                ev = self.resolver.resolve(choice, s)        # ③ 執行層：屬性對抗
            self.apply(ev)                                   # 比分、控球、統計、事件流
            self.referee.judge(ev, s)                        # 犯規、出牌、有利原則、VAR
            self.injuries.check(ev, s)
            self.fatigue.tick(ev.duration, s)                # ④ 狀態層
            self.managers.think(s)                           # 換人、戰術調整
            self.clock.advance(ev.duration, ev.dead_time)
        return self.post_match()
```

**隨機數**：每場比賽用 `np.random.SeedSequence(seed).spawn(k)`，讓每個子系統（決策、執行、裁判、傷病）各有獨立的隨機流。這樣同一個種子可以完整重播；做敏感度分析時，改動一個屬性也不會打亂其他子系統的隨機序列，讓共同隨機數（CRN）的變異縮減效果更好。

### 4.3 時間模型

每個事件消耗兩種時間：「動作時長」（球在場上）與「死球時間」（球不在場上）。

| 事件 | 動作時長 | 死球時間 |
|---|---|---|
| 短傳（含接球） | 1.2–2.5 s | — |
| 長傳、轉移 | 2.0–3.5 s | — |
| 帶球推進 | 1.5–5 s（依距離與速度） | — |
| 過人 | 1–2.5 s | — |
| 界外球 | — | 10–25 s |
| 球門球 | — | 20–35 s |
| 角球 | — | 25–45 s |
| 自由球 | — | 20–60 s（危險區域較久） |
| 進球（慶祝 + 開球） | — | 60–90 s |
| 換人 | — | 25–45 s |
| 傷停處理、VAR 檢查 | — | 60–180 s |

- 「節奏」戰術會把動作間隔乘上 0.8–1.2；開啟「拖延時間」會讓死球時間 ×1.2–1.5。
- **補時** = 該半場的非常態死球時間總和（進球、換人、傷停、VAR、拖延）× 裁判係數，無條件進位到整分鐘。
- 校準目標：淨比賽時間約 55–60 分鐘、雙方合計約 900–1,000 次傳球。

### 4.4 空間模型

**座標系**：球場 105 × 68 m（可依主場設定）。每隊的進攻方向統一轉成由左往右（x：0 → 105）。

**價值網格**：xT（Expected Threat，16 × 12 網格）。可用 StatsBomb 開放資料計算，或直接使用 socceraction 套件。用途有三：決策的價值函數、球員評分、進攻威脅統計。

**陣型快照**：每個事件前，依下式計算 22 人的位置：

```
p_i = A_i(陣型, 角色, 階段)                 # 陣型模板：持球與無球各一套
    + S(球的位置, 防線高度, 寬度, 比分情境)  # 整隊平移與壓縮
    + M_i(角色行為)                          # 套邊、內收、後插上、回撤
    + Q_i(個人站位品質)                      # 屬性在這裡發揮作用（見下）
    + ε_i                                    # 雜訊
```

- **整隊平移**：防線 x = 防線高度基準 + α × (球的 x − 52.5)；橫向往球側平移 β × (球的 y − 34)，β 約 0.3–0.5。
- **隊伍縱深**（最後一名後衛到最前鋒的距離）由戰術決定，並隨平均疲勞拉長。陣型在比賽末段被拉開，正是「進球集中在下半場」的機制來源（實測下半場進球占 55.4%）。
- **進攻站位品質**：每位進攻球員在角色區域內抽樣 K 個候選點，K = 1 + ⌊off_the_ball / 20⌋，也就是 1–6 個；選出「xT × 開闊度 × 是否在越位位置之外」分數最高的點。跑位好的球員因此**穩定地**站到更好的位置。
- **防守站位誤差**：σ = 0.5 + 3.5 × (1 − q) 公尺，其中 q = (0.5 × 防守站位 + 0.3 × 專注 + 0.2 × 團隊配合) / 100，再乘上位置熟練度與心智疲勞係數。
- **恍神（lapse）**：每個控球回合以 p = 0.02 × (1.5 − 專注/100) × (1 + 疲勞) 的機率發生；發生時，該回合的 σ 變成 3 倍。
- **回防**：進攻球員在無球時是否回到防守區塊，機率由投入度決定。回防會增加球後方的人數；不回防則保留反擊點。這是真實的戰術取捨。
- **湧現現象**：邊後衛套邊與邊鋒形成 2 對 1、高防線的身後空間、低位防守的禁區擁擠，都會從幾何關係中自然產生，不需要寫死規則。

**壓迫值**（作用在持球者身上）：

```
P = Σ_j exp(−d_j² / (2 · 3²)) × press_j / R
press_j = 壓迫複合能力（投入度 .30、侵略性 .20、加速 .20、預判 .15、團隊配合 .15）× 能量係數
```

壓迫會影響執行（§4.7）、停球失誤率，以及決策溫度（§4.6）。

### 4.5 屬性影響的四層模型

這是「屬性真的能影響比賽」的核心架構：每個屬性至少在其中一層發揮作用。

```
① 位置/感知層：站到哪裡、看見什麼
   無球跑位、防守站位、預判、專注、團隊配合、投入度、視野、位置熟練度
        ↓ 決定「場面」：誰有空間、誰被盯死、有哪些選項
② 決策層：選擇哪個動作
   決策、視野、冷靜、創造力、團隊配合 ＋ 特質 ＋ 戰術偏好
        ↓ 決定「選擇」
③ 執行層：動作成功與否、品質好壞
   技術與身體屬性 vs 對手屬性（logit 對抗、物理模型）
        ↓ 決定「結果」
④ 狀態層：修正以上三層
   體能、信心、士氣、當日狀態（穩定性）、大場面、熟悉度、天氣、場地
```

**範例：一次直塞**

1. **位置層**：前鋒（無球跑位 88）在越位線上找到中衛身後的空間。
2. **決策層**：中場（視野 85）「看見」了這條傳球線路，並在 softmax 中選擇它。
3. **執行層**：傳球（短傳 82、腳法 80）穿過攔截線；前鋒（速度、加速皆 85）在 25 m 的衝刺競速中，以 85% 的機率贏過中衛（皆 65）。
4. **狀態層**：第 85 分鐘，中衛能量只剩 0.45，身體屬性 ×0.887，前鋒贏下這次競速的機率從 85% 升到 92%（✔ 已驗證，模型見 §4.9）。

### 4.6 決策系統

**(1) 選項生成（感知）**

- **傳球**：每位隊友。另加上傳到跑動者前方空間的直塞；這類選項要先被「看見」，機率 = σ((視野 − 難度) / 8)，難度與距離、穿透程度、是否需要轉身有關。
- **帶球推進**：朝前方開闊方向的 3–5 個選項。
- **過人**：前方 3 m 內有防守者時才產生。
- **射門**：進入射程才產生。
- **傳中、倒三角**：在邊路的進攻三區。
- **護球、回傳、解圍**：受壓或在本方禁區時。

**(2) 評估**

```
U_i = p̂_i × V_succ,i + (1 − p̂_i) × V_fail,i + B_戰術 + B_特質 + B_創造力
```

- p̂_i 是球員**主觀估計**的成功率 = 真實成功率 + 誤差。誤差隨決策降低、壓迫升高、疲勞升高而增加。
- V_succ = 終點的 xT；射門則為 xG。V_fail = −(對手在丟球位置的反擊威脅) × 風險權重 λ。λ 由心態與比分情境決定，領先時 λ 較高。
- 射門選項的效用 = 預估 xG − 保持球權的價值 + 射門策略修正。因此決策好的球員**射門選擇更好**（平均 xG 較高），這與現實一致。

**(3) 選擇**：softmax，溫度 T = T0 × (1.5 − 決策/100) × (1 + 0.5 × 壓迫 × (1 − 冷靜/100))。

✔ 已驗證（5 個選項，效用 0.05 / 0.03 / 0.01 / 0 / −0.02，單位為 xT）：

| 決策 | 冷靜 | 壓迫 | 選中最佳選項 | 選中最差選項 | 期望價值 |
|---|---|---|---|---|---|
| 90 | 65 | 0 | 80% | 0.2% | 0.0450 |
| 65 | 65 | 0 | 68% | 1.1% | 0.0407 |
| 40 | 65 | 0 | 58% | 2.4% | 0.0368 |
| 90 | 40 | 1.0 | 71% | 0.8% | 0.0419 |
| 40 | 40 | 1.0 | 50% | 4.3% | 0.0328 |

決策的作用明顯，但不是決定論：頂尖球員偶爾也會做出錯誤選擇。

**創造力**：它在選擇時，為「低機率、高回報」的選項加分；在執行時，增加結果變異（logit 加上 N(0, 0.5 × flair/100) 的雜訊）。技術高的球員因此受益，技術低的球員反而受害。這不是寫死的規則，而是自然湧現的結果。

### 4.7 動作解析：通用公式

```
logit(p) = logit(p_base(情境)) + k_a × (A − R)/10 − k_d × (D − R)/10 + Σ 修正
```

- **p_base(情境)**：R 水準球員在此情境下的真實成功率，用事件資料擬合（傳球距離、傳球線上的防守者、壓迫、傳球類型等）。
- **A、D**：攻方與守方的複合能力 = 屬性向量 · 權重向量（權重見 §4.8）。屬性已先套用狀態層的修正。
- **k_a 與 k_d**：每 10 點能力差造成的 logit 位移。k_a > k_d 代表結果主要由執行者決定（例如傳球）；k_a = k_d 代表純粹的對抗（例如過人）。這個「絕對項 + 相對項」的設計，讓低級別聯賽的傳球成功率自然下降。
- **修正項**：壓迫 −0.9 × P × (1.25 − 冷靜/100)、逆足、天氣、場地、默契、戰術熟悉度、信心。

### 4.9 物理子模型

**衝刺（Furusawa 模型）**：v(t) = v_max · (1 − e^(−t/τ))，其中 v_max = 7.6 + 0.022 × 速度（m/s），τ = 1.0 − 0.004 × 加速（s）。用牛頓法求出「跑 d 公尺所需的時間」。每位球員的參數在賽前預先計算，疲勞時再打折。

✔ 已驗證：

| 類型（速度 / 加速） | 最高速 | 5 m | 10 m | 20 m | 30 m | 40 m |
|---|---|---|---|---|---|---|
| 平均 60 / 60 | 32.1 km/h | 1.15 s | 1.81 s | 2.99 s | 4.12 s | 5.24 s |
| 頂尖 90 / 90 | 34.5 km/h | 1.03 | 1.63 | 2.72 | 3.77 | 4.82 |
| 高速慢啟動 90 / 50 | 34.5 km/h | 1.13 | 1.75 | 2.87 | 3.93 | 4.97 |
| 爆發型 50 / 90 | 31.3 km/h | 1.10 | 1.75 | 2.93 | 4.09 | 5.24 |
| 慢速 40 / 40 | 30.5 km/h | 1.24 | 1.94 | 3.18 | 4.37 | 5.56 |

- 這些數字與職業球員的實測量級相符：10 m 約 1.7–1.9 s、30 m 約 4.0–4.3 s，比賽中的最高速約 31–35 km/h。
- **情境決定屬性價值（P3），由物理自然產生**：「高速慢啟動」與「爆發型」在 **11.5 m** 處交叉。前者贏得競速的機率在 5 m 時是 0.45，10 m 時 0.49，20 m 時 0.64，30 m 時 0.79，40 m 時 0.90。所以速度在反擊與身後球時很重要，在狹小空間裡則是加速與敏捷較重要。
- **競速判定**：抵達時間 = 反應延遲 + 跑完距離所需時間。反應延遲由預判決定；預先設計好的跑動則由無球跑位決定，並且能「提前起跑」。攻方先到球的機率 = σ((t_守 − t_攻) / 0.12 s)。

**爭頂（有效高度）**：有效高度 = 身高 + 起跳（35 + 0.30 × 彈跳 cm）。門將的觸球高度改用「1.33 × 身高 + 起跳」，因為門將可以用手。

```
logit = 0.07 × 有效高度差(cm) + 0.025 × 時機差 + 0.015 × 力量差 + 0.010 × 勇敢差
時機 = 0.6 × 預判 + 0.4 × 頭槌
```

### 4.12 攻防轉換

- **斷球瞬間**計算轉換優勢 = 球前方可用的進攻人數 − 對方在球後方的防守人數，再加上空間因子（斷球位置到對方球門的距離）。
- **丟球方**：開啟「就地反搶」時，5 秒內附近球員施加壓迫，強度取決於投入度、侵略性與能量。成功就能在前場奪回球權；失敗則要面對失衡的防線。
- **反擊模式**：節奏提高，直塞與推進選項加分，衝刺競速變得頻繁。速度的價值在這時自然上升。
- **戰術犯規**：反擊危險度高、防守者已被突破時，犯規機率取決於骯髒度、比分情境、自己是否已吃黃牌。

### 4.13 體能與疲勞

```
每分鐘能量消耗 = 0.0040 × 強度(角色, 戰術, 天氣, 海拔) × (1.4 − 0.8 × 耐力/100) × (0.8 + 0.4 × 投入度/100)
中場休息恢復   = 0.04 + 0.04 × 恢復力/100
身體屬性乘數   = 能量 ≥ 0.75 時為 1.0，之後線性下降（斜率 0.375），下限 0.80
心智屬性乘數   = 能量 ≥ 0.60 時為 1.0，之後下降，鬥志可抵銷一部分，下限 0.90
```

- 「高位壓迫 + 低耐力 → 末段崩盤」會自然出現。

### 4.15 比分情境與教練 AI

- **比分 × 時間 → 心態調整**：落後時提高心態（防線前壓、更多人前插、射門門檻降低、更多傳中）；領先時降低心態（拖延、解圍、增加防守人數）。這會讓落後方的控球與射門比例上升，正如現實。
- **換人的觸發順序**：受傷 > 紅牌後補位 > 體能（能量 < 0.55 且已過 60 分鐘）> 吃黃牌的高風險防守者 > 戰術需要（落後時換上攻擊手）> 賽中評分 < 6.0。並遵守 5 人、3 次窗口的規則。
- **總教練的屬性**：臨場調度能力決定換人時機的誤差與選對替補的機率；戰術知識決定調整是否正確。
- **實測動態目標**：半場領先的一方最終勝 **73.4%**、和 **17.7%**、負 **9.0%**。引擎必須重現這個結果，代表比分情境與體能機制的強度是對的。

### 4.16 裁判、紀律與 VAR

**犯規機率**：

```
logit P(犯規 | 搶斷) = β_f + 0.25 × (持球者能力 − 搶斷能力)/10 + 0.2 × (侵略性 − 50)/10
                       + 0.15 × (骯髒度 − 50)/10 + 搶斷力度戰術 + 疲勞 + 裁判嚴格度
```

- **嚴重度分級**：一般犯規（自由球）、魯莽（黃牌）、使用過度力量（紅牌）。阻止有希望的進攻（SPA）→ 黃牌；破壞明顯的進球機會（DOGSO）→ 紅牌；但在禁區內且有爭球意圖時，依 IFAB 規則降為黃牌。
- **其他**：有利原則、抗議與拖延吃牌（脾氣、運動精神、拖延戰術）、兩黃變一紅、紅牌後由教練 AI 自動重組陣型。
- **聯賽風格參數**：實測每隊每場犯規，英超 10.9、西甲 12.7；每場紅牌，英超 0.12、西甲 0.27。這些差異主要來自裁判文化，因此裁判參數要分聯賽設定。
- **主場哨**：實測主隊吃到的黃牌占 46.6%，但 2020/21 空場賽季為 **49.3%**，接近中立。所以主場哨的強度要與觀眾數成正比（§4.18）。
- **VAR**：檢查進球（越位、犯規、手球）、十二碼與直接紅牌；有一定機率改判，並增加死球時間。

### 4.17 傷病

- **接觸傷**：每次對抗時判定，取決於對抗強度、受害者的易傷性、疲勞與年齡；勇敢會增加曝險，力量會降低受傷機率。
- **非接觸傷**（肌肉）：每分鐘的風險率，與衝刺次數、疲勞、ACWR、年齡、易傷性、氣溫有關。
- **嚴重度**：輕微（可繼續比賽，屬性 −5% 到 −15%）、需要換下、長期缺陣（天數取對數常態分布）。類型包括肌肉拉傷、扭傷、挫傷、韌帶傷等。
- **校準目標**：比賽傷病發生率約每千小時 20–30 次（UEFA 菁英俱樂部傷病研究的量級），約等於每隊每場 0.35–0.5 次（含賽後才確診的輕傷）。

### 4.18 主場優勢、天氣與場地

**主場優勢不寫死成「+X 進球」，而是由四個機制組成**：

| 機制 | 是否依賴觀眾 | 作用 |
|---|---|---|
| 觀眾壓力 | 是 | 客隊冷靜下降 |
| 主場哨 | 是 | 犯規與出牌的門檻輕微偏向主隊 |
| 場地熟悉 | 否 | 主隊停球、短傳 +1–2 點 |
| 旅途疲勞 | 否 | 客隊賽前體能、時差 |

**實測校準靶**（同時重現兩組數據，才能證明機制的拆解是對的）：

| 期間 | 主勝 / 和 / 客勝 | 主隊 / 客隊進球 | 主隊射門占比 | 主隊黃牌占比 |
|---|---|---|---|---|
| 2022/23–2025/26（有觀眾） | 43.7% / 25.3% / 31.0% | 1.55 / 1.26 | 55.1% | 46.6% |
| 2020/21（絕大多數為空場） | 39.9% / 25.5% / 34.7% | 1.48 / 1.32 | 53.2% | 49.3% |

把觀眾數設為 0 時，模擬結果應該往第二列移動：主場哨消失，但主場優勢沒有完全消失。

**天氣**：
- 雨天：地面傳球變快、停球難度上升、門將接球容易脫手、可能滑倒。
- 強風：長傳、傳中、遠射的誤差增加。
- 高溫：能量消耗 ×1.1–1.25。
- 高海拔：未適應的隊伍能量消耗增加。

**場地**：品質差時技術動作打折；球場較大時空間較多，速度與耐力的價值上升；人工草皮的球速較快。

## 5. 戰術系統

每個戰術參數都有**效益，也有代價**。沒有萬能戰術，才符合現實。

| 參數 | 選項 | 引擎作用 | 代價與風險 |
|---|---|---|---|
| 陣型 | 4-3-3、4-2-3-1、4-4-2、3-5-2、5-3-2 等 | 陣型模板（持球與無球各一套） | 各區人數不同 → 局部人數優劣、寬度 |
| 角色與職責 | §3.4 | 位置偏移、動作偏好 | 能量消耗、適配度 |
| 心態 | 1–5 | 風險權重 λ、前插人數、射門門檻 | 前插越多，留守越少，越容易被反擊 |
| 防線高度 | 1–5 | 防線的 x 座標、隊伍縱深 | 防線高：壓縮空間、越位多；但身後空間大，中衛速度與門將清道夫能力的價值上升 |
| 壓迫線與強度 | 1–5 | 壓迫值、上搶頻率 | 能量消耗、犯規增加；被打穿時防線失衡 |
| 寬度 | 1–5 | 持球時的橫向展開 | 寬：更多傳中與轉移；窄：中路配合多，但容易擁擠 |
| 節奏 | 1–5 | 動作間隔、偏好向前的選項 | 失誤、能量消耗、回合數都會增加 |
| 傳球方式 | 短、混合、直接 | 長傳選項加權 | 直接：爭頂與第二落點的比重上升、控球率下降 |
| 後場組織 | 門將短傳或長傳 | 球門球的選擇 | 短傳面對高位壓迫時有丟球風險 |
| 進攻重點 | 左、中、右、平衡 | 選項加權 | 可以針對對方的弱點 |
| 傳中方式 | 早傳、下底、倒三角 | 傳中位置與類型 | 倒三角的 xG 高，但要先突破到底線 |
| 射門策略 | 見機就射、打進禁區 | 射門的 xG 門檻 | 門檻低 → 射門多但品質低 |
| 攻轉守 | 就地反搶、回收 | 丟球後 5 秒的行為 | 反搶失敗 → 被反擊 |
| 守轉攻 | 反擊、控球重整 | 斷球後的節奏 | — |
| 盯人方式 | 區域、人盯人、混合 | 防守站位邏輯 | 人盯人時個人對位的影響更大，也更容易被拉扯 |
| 搶斷力度 | 保守、一般、兇狠 | 搶斷嘗試率、犯規率 | 兇狠：吃牌與送十二碼的風險上升 |
| 越位陷阱 | 開、關 | 防線同步前壓 | 協同失敗 → 對方單刀 |
| 拖延時間 | 開、關 | 死球時間增加 | 黃牌風險上升 |
| 定位球 | 套路、盯人方式、留守人數 | 角球與自由球的解析 | 留守人數少 → 容易被反擊 |

**戰術熟悉度**（0–100）：數值低時，位置誤差變大、壓迫協同與越位陷阱的成功率下降。熟悉度隨訓練與比賽成長；團隊配合高的球員學得比較快。

### 6.4 校準流程（由下而上，五層）

| 層級 | 內容 | 方法 |
|---|---|---|
| L1 動作層 | 每個解析函數在 R 水準時吻合事件資料 | 直接用 StatsBomb 擬合邏輯斯迴歸，不需要整場模擬 |

| L3 實力梯度 | 不同實力差距的對戰，吻合 §6.3 與半場領先的統計 | 用能力差掃描建立勝率曲線 |
| L4 賽季層 | 模擬 1,000 個 20 隊 38 輪的賽季：冠軍積分、降級線、積分標準差、熱門勝率 | 隊伍實力的分散程度由真實積分表反推 |

### 6.5 敏感度分析：證明屬性真的有用

**流程**：對每個屬性 a 與其相關的位置群組 g，把基準隊伍在 g 中的 a 加 10 點（上限 100），用**同一組隨機種子**（共同隨機數）配對模擬 4,000 場，量測淨勝球、勝率與相關統計的變化（附錄 D）。

**四項自動檢查**：

| 檢查 | 失敗條件 |
|---|---|
| 死屬性 | 淨勝球與其主要統計指標的變化都小於 2 個標準誤 |
| 壓倒性屬性 | 單一屬性 +10 的淨勝球效益，超過「全部屬性同時 +10」效益的 25% |
| 方向錯誤 | 符號與預期相反（例如侵略性上升，犯規卻下降） |
| 情境性 | 中衛的速度對「反擊型對手」的效益，必須大於對「控球型對手」的效益 |

### 6.6 驗收標準

1. §6.1 的每項指標落在五大聯賽的範圍內，或與合併值的相對誤差 ≤ 5%；比例型指標的誤差 ≤ 2 個百分點。
2. 總進球分布（0 到 7+）與實測的總變異距離 ≤ 0.03。
3. 實力梯度：各組的勝、和、負比例誤差都 ≤ 3 個百分點。
4. 敏感度分析：沒有死屬性、沒有壓倒性屬性、沒有方向錯誤。
5. 次級聯賽交叉驗證通過。

## 8. 賽季與生涯層

- **賽程**：雙循環賽程（circle method）、盃賽、國際比賽日。
- **賽間恢復**：體能每日恢復，速度由恢復力、休息天數與醫療團隊決定（約 72 小時恢復到 95%）。比賽感覺沒上場就會衰退。
- **負荷與傷病（ACWR）**：急性負荷（7 日）/ 慢性負荷（28 日週平均）> 1.5 時，傷病風險 ×1.5–2。文獻上仍有爭議，但很適合遊戲化，並能讓「賽程密集 → 輪換」成為必要的決策。
- **近況與士氣**：評分的指數加權平均、勝負結果、上場時間（受企圖心影響）。
- **成長**：每月成長 = 年齡係數 × (潛力 − 現況) × 訓練品質 × 職業態度 × 上場時間係數。

```python
"""engine/core_math.py — 比賽引擎核心公式（結構已定案，係數待校準）"""
from __future__ import annotations

import math

import numpy as np

R = 65.0  # 參考水準：頂級聯賽平均球員


def sigmoid(z: float) -> float:
    return 1.0 / (1.0 + math.exp(-z))


def logit(p: float) -> float:
    return math.log(p / (1.0 - p))


# ---------------------------------------------------------------- 1. 屬性對抗
def duel_prob(base_p: float, att: float, dfn: float,
              k_att: float = 0.35, k_def: float = 0.35, mods: float = 0.0) -> float:
    """base_p：R 水準雙方在此情境下的真實成功率（由事件資料擬合）。
    att / dfn：攻、守方的複合能力（1–100）。k_*：每 10 點能力差的 logit 位移。"""
    z = logit(base_p) + k_att * (att - R) / 10 - k_def * (dfn - R) / 10 + mods
    return sigmoid(z)


def pressure_mod(pressure: float, composure: float, c: float = 0.9) -> float:
    """壓迫懲罰（加在 logit 上）。冷靜越高，壓迫的影響越小。"""
    return -c * pressure * (1.25 - composure / 100)


# ---------------------------------------------------------------- 2. 衝刺（Furusawa 模型）
def vmax_ms(sprint_speed: float) -> float:
    """最高速度 m/s：1 → 7.6（27 km/h），100 → 9.8（35 km/h）"""
    return 7.6 + 0.022 * sprint_speed


def tau_s(acceleration: float) -> float:
    """加速時間常數 s：越小越有爆發力。1 → 1.0，100 → 0.6"""
    return 1.00 - 0.004 * acceleration


def sprint_time(d: float, vmax: float, tau: float) -> float:
    """由靜止跑 d 公尺所需秒數；解 d = vmax·(t − τ·(1 − e^(−t/τ)))"""
    t = d / vmax + tau
    for _ in range(8):  # 牛頓法，3–4 次即收斂
        e = math.exp(-t / tau)
        t -= (vmax * (t - tau * (1 - e)) - d) / (vmax * (1 - e))
    return t


def race_prob(t_att: float, t_def: float, noise: float = 0.12) -> float:
    """攻方先到球的機率；t_* 已含反應延遲"""
    return sigmoid((t_def - t_att) / noise)


# ---------------------------------------------------------------- 3. 爭頂（有效高度）
def jump_cm(jumping: float) -> float:
    return 35 + 0.30 * jumping  # 1 → 35 cm，100 → 65 cm


def aerial_prob(a: dict, d: dict) -> float:
    """a / d 需含 height, jumping, anticipation, heading, strength, bravery"""
    dh = (a["height"] + jump_cm(a["jumping"])) - (d["height"] + jump_cm(d["jumping"]))

    def timing(p: dict) -> float:
        return 0.6 * p["anticipation"] + 0.4 * p["heading"]

    z = (0.07 * dh                                   # 每高 1 cm
         + 0.025 * (timing(a) - timing(d))           # 起跳時機
         + 0.015 * (a["strength"] - d["strength"])   # 身體碰撞
         + 0.010 * (a["bravery"] - d["bravery"]))    # 敢不敢頂
    return sigmoid(z)


# ---------------------------------------------------------------- 4. 射門（xG → 射正 → 門將）
GOAL_W = 7.32


def shot_geometry(x: float, y: float) -> tuple[float, float]:
    """x：離球門線的距離(m)，y：與球門中心的橫向偏移(m)。回傳 (距離, 兩柱夾角 rad)"""
    ang = math.atan2(GOAL_W * x, x * x + y * y - (GOAL_W / 2) ** 2)
    if ang < 0:
        ang += math.pi
    return math.hypot(x, y), ang


# 起始係數：以 13 個位置錨點擬合（平均相對誤差 14%）；正式版改用 StatsBomb 射門資料重新擬合，
# 並加入 助攻類型 / 是否一腳射門 / 防守人數 / 門將位置 / 是否反擊 等特徵
XG_COEF = {"b0": -0.489, "b_dist": -0.041, "b_logang": 1.509, "b_head": -0.8}


def base_xg(x: float, y: float, header: bool = False) -> float:
    dist, ang = shot_geometry(x, y)
    z = XG_COEF["b0"] + XG_COEF["b_dist"] * dist + XG_COEF["b_logang"] * math.log(ang)
    if header:
        z += XG_COEF["b_head"]
    return sigmoid(z)


def shot_outcome_probs(xg: float, shooter: float, gk: float,
                       p_block: float = 0.26, p_ot_base: float = 0.47,
                       k_ot: float = 0.12, k_place: float = 0.06, k_gk: float = 0.20) -> dict:
    """兩階段：射手決定射正率與落點品質（→ PSxG），門將決定撲救。
    基準分解：xG = (1 − p_block) · p_ot_base · p_goal_given_ot_base"""
    p_g_ot_base = min(0.97, xg / ((1 - p_block) * p_ot_base))
    p_ot = sigmoid(logit(p_ot_base) + k_ot * (shooter - R) / 10)
    p_g_ot = sigmoid(logit(p_g_ot_base) + k_place * (shooter - R) / 10 - k_gk * (gk - R) / 10)
    return {"blocked": p_block, "on_target": (1 - p_block) * p_ot,
            "goal": (1 - p_block) * p_ot * p_g_ot, "save_rate": 1 - p_g_ot}


# ---------------------------------------------------------------- 5. 體能
def energy_drain_per_min(stamina: float, work_rate: float, intensity: float = 1.0,
                         d0: float = 0.0040) -> float:
    return d0 * intensity * (1.4 - 0.8 * stamina / 100) * (0.8 + 0.4 * work_rate / 100)


def physical_factor(energy: float) -> float:
    """身體屬性乘數：能量 ≥ 75% 時無影響，之後線性下降，下限 0.80"""
    return 1.0 if energy >= 0.75 else max(0.80, 1.0 - 0.375 * (0.75 - energy))


def mental_factor(energy: float, determination: float) -> float:
    """心智屬性乘數：能量 < 60% 才開始下降；鬥志可以抵銷一部分"""
    if energy >= 0.60:
        return 1.0
    return max(0.90, 1.0 - 0.27 * (0.60 - energy) * (1.2 - determination / 100))


# ---------------------------------------------------------------- 6. 決策
def choice_probs(utilities, decisions: float, composure: float, pressure: float,
                 t0: float = 0.02) -> np.ndarray:
    """softmax 選擇：決策越高 → 溫度越低 → 越常選中最佳選項；壓迫會拉高溫度"""
    temp = t0 * (1.5 - decisions / 100) * (1 + 0.5 * pressure * (1 - composure / 100))
    u = np.asarray(utilities, dtype=float) / temp
    p = np.exp(u - u.max())
    return p / p.sum()
```

"""calibration/targets.py — 由 football-data.co.uk CSV 計算校準目標"""
import sys
from pathlib import Path

import numpy as np
import pandas as pd

DATA = Path(sys.argv[1])
TOP5 = ["E0", "SP1", "D1", "I1", "F1"]
COLS = ["FTHG", "FTAG", "FTR", "HTHG", "HTAG", "HS", "AS", "HST", "AST",
        "HF", "AF", "HC", "AC", "HY", "AY", "HR", "AR", "B365H", "B365D", "B365A"]


def load(div):
    frames = []
    for f in sorted(DATA.glob(f"*_{div}.csv")):
        try:
            df = pd.read_csv(f, encoding="utf-8-sig")
        except UnicodeDecodeError:
            df = pd.read_csv(f, encoding="latin-1")
        frames.append(df[[c for c in COLS if c in df.columns]].dropna(subset=["FTHG", "FTAG"]))
    return pd.concat(frames, ignore_index=True)


def summarize(df):
    g, ht = df.FTHG + df.FTAG, df.HTHG + df.HTAG
    lead_h, lead_a = df.HTHG > df.HTAG, df.HTAG > df.HTHG
    led = lead_h | lead_a
    win = (lead_h & (df.FTR == "H")) | (lead_a & (df.FTR == "A"))
    o = df[["B365H", "B365D", "B365A"]].dropna()
    p = (1 / o.values) / (1 / o.values).sum(axis=1, keepdims=True)   # 去除抽水
    res = df.loc[o.index, "FTR"].map({"H": 0, "D": 1, "A": 2}).values
    fav = np.where(p[:, 0] >= p[:, 2], 0, 2)
    return {
        "goals_pm": g.mean(), "goals_var_over_mean": g.var() / g.mean(),
        "home_goals": df.FTHG.mean(), "away_goals": df.FTAG.mean(),
        "H%": (df.FTR == "H").mean() * 100, "D%": (df.FTR == "D").mean() * 100,
        "A%": (df.FTR == "A").mean() * 100,
        "0-0%": ((df.FTHG == 0) & (df.FTAG == 0)).mean() * 100,
        "corr_home_away": np.corrcoef(df.FTHG, df.FTAG)[0, 1],
        "2H_goal_share%": (g - ht).sum() / g.sum() * 100,
        "shots_pt": (df.HS + df.AS).mean() / 2, "sot_pt": (df.HST + df.AST).mean() / 2,
        "sot_ratio%": (df.HST + df.AST).sum() / (df.HS + df.AS).sum() * 100,
        "goals_per_shot%": g.sum() / (df.HS + df.AS).sum() * 100,

## 附錄 D：敏感度分析骨架（M4 實作）

```python
"""calibration/sensitivity.py — 屬性敏感度分析（骨架；simulate、boost 於 M1–M3 實作）"""
from concurrent.futures import ProcessPoolExecutor

import numpy as np


def paired_run(args):
    team, opponent, attr, group, delta, seed = args
    boosted = boost(team, attr, group, delta)        # 指定位置群組的屬性 +delta（上限 100）
    r0 = simulate(team, opponent, seed=seed)         # 共同隨機數：同一個種子
    r1 = simulate(boosted, opponent, seed=seed)
    return r1.goal_diff - r0.goal_diff, r1.points - r0.points, r1.key_stats - r0.key_stats


def sensitivity(team, opponents, plan, n=4000, delta=10):
    """plan: {屬性: [位置群組, ...]}，例如 {"sprint_speed": ["CB", "ST"]}"""
    rows = []
    with ProcessPoolExecutor() as ex:
        for attr, groups in plan.items():
            for group in groups:
                jobs = [(team, opponents[i % len(opponents)], attr, group, delta, 10_000 + i)
                        for i in range(n)]
                d_gd, d_pts, d_stats = map(np.array, zip(*ex.map(paired_run, jobs, chunksize=64)))
                rows.append({"attr": attr, "group": group,
                             "d_goal_diff": d_gd.mean(),
                             "se": d_gd.std(ddof=1) / np.sqrt(n),
                             "d_points": d_pts.mean(),
                             "d_stats": d_stats.mean(axis=0)})
    return rows
```
